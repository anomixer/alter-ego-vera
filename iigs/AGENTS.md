## Hard constraints found in this port

### `y_offset` and upper sprite bodies

The current configuration is:

- `iigs/src/games/alterego/Config.s`: `y_offset equ 0`
- `iigs/src/ppu/ppu.s`: `SPR_SETUP` adds `#$2000+x_offset` (no `y_offset` subtraction)

With a non-zero `y_offset` the background scrolls up, but in this port the **upper half of the 8×16
player/enemy sprites disappears** (feet remain). This was reproduced at `y_offset=2`, `4`, `8`; at
`y_offset=0` the bodies are complete. Do not "just bump `y_offset`" for the layout request without
verifying the sprite tops on GSplus. The earlier workaround of removing the `y_offset` subtraction
from `SPR_SETUP` did not fix it by itself in the tested y2 build.

The planned correct direction for the layout request is to render the level name/HUD and the
playfield as separate bands, so only the playfield moves; the naive global `y_offset` is not safe as
implemented.

### Conditional blitter scrolling is unsafe

Adding a `cmp #HUD_FIXED_LINES` / conditional `add_y_offset` in
`iigs/src/core/blitter/BlitterLite.s` caused GSplus **`Emulated state corrupt`**, a black screen or a
System 6 reboot. Both macro-local and inline variants failed. The three `add_y_offset` sites are back
to unconditional. Do not retry the same per-line conditional in the blitter without a different
strategy.

### `POST_RENDER` direct SHR writes

A `POST_RENDER` hook that wrote a bottom border directly into `$E1/2000 + row*160` also led to a
corrupt boot (likely a bad/stale `ScreenY1`/address path during the title). That code was removed.
If a border/overlay is needed later, it must be gated on a valid game screen and verified in GSplus.

### Audio

The current image is built from the **audio-off PRG**. Audio-enabled app builds (264,075 and 268,210
bytes) crashed GSplus with `Emulated state corrupt`; audio remains unverified. `prg_before_audio.bin`
in the old silky working tree was the known-good PRG source, and the committed `prg.bin` is that
baseline.

### Emulator / packaging gotchas

- Launch GSplus with `-cfg <file>`, **not** `-kegs`.
- `cadius` uses `REPLACEFILE`; `LIST` is invalid (`CATALOG` is the listing command).
- Do not move/resize the GSplus window; capture the existing window rectangle.
- `prg.bin` must be exactly 32,768 bytes; `__ROM0_LAST__` is `00F6B3`.
